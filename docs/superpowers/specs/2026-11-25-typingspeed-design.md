# typingspeed.nvim — спецификация

Дата: 2026-11-25
Целевая версия: Neovim 0.12+ (проверено на 0.12.6)

## Назначение

Плагин для Neovim показывает текущую скорость печати в statusline. Значения должны быть
сопоставимы с тренажёрами (monkeytype и аналоги): основная метрика — чистая скорость,
то есть символы, оставшиеся в тексте, за единицу времени.

## Требования

1. Показывается текущая скорость за скользящее окно времени (по умолчанию 10 с).
2. Единицы настраиваются: `wpm` (по умолчанию, 1 слово = 5 символов) или `cpm`.
3. Отображение — функция `require('typingspeed').status()`, возвращающая строку для
   statusline (`"62 wpm"`) или `""`, если данных нет.
4. Подсчёт чистый: набранные пользователем символы минус символы, удалённые в Insert mode.
5. Учитывается только ручной ввод. Вставки через API (автодополнение, сниппеты),
   раскрытие маппингов (закрывающая скобка автопары), повтор `.` и макросы не учитываются.
6. Учитываются только обычные файловые буферы (`buftype == ""`).

Вне объёма: история и статистика на диске, плавающее окно, virtual text, учёт
неисправленных ошибок (эталонного текста нет, поэтому обнаружить их невозможно).

## Архитектура

```
lua/typingspeed/
  init.lua     -- публичный API: setup(opts), status()
  config.lua   -- значения по умолчанию, слияние и проверка опций
  meter.lua    -- чистая логика: очередь событий → скорость; без API Neovim
  tracker.lua  -- связка с Neovim: on_key, InsertCharPre, InsertLeave, таймер
tests/
  run.lua      -- минимальный раннер, запуск: nvim --headless -l tests/run.lua
  meter_spec.lua
  tracker_spec.lua
Makefile       -- цель test
README.md
```

### meter.lua

Чистый модуль, время передаётся параметром (миллисекунды).

- `meter.new({ window_ms, warmup_ms })` → объект.
- `m:add(t, delta)` — добавить событие `{t, delta}`; `delta` = +1 за символ, −N за удаление.
  Если очередь была пуста, `streak_start = t`.
- `m:rate(now)` → символов в минуту (число) или `nil`:
  - удалить события с `t < now − window_ms`; если очередь пуста — вернуть `nil`;
  - `elapsed = min(window_ms, now − streak_start)`;
  - если `elapsed < warmup_ms` (2000) — вернуть `nil`;
  - `net = max(0, Σ delta)`; вернуть `net / elapsed × 60000`.
- `m:empty(now)` → `true`, если после очистки устаревших событий очередь пуста.

### tracker.lua

Подписывается на события Neovim и передаёт их в `meter`. Время берётся из `clock()`,
по умолчанию `vim.uv.hrtime() / 1e6`; в тестах подменяется.

Состояние:
- `user_insert` (bool) — относится ли текущая клавиша к ручному вводу в Insert mode
  (наследуется клавишами с пустым `typed`); используется для удалений и `<CR>`/`<Tab>`;
- `key_typed` (bool) — текущая клавиша нажата пользователем в Insert mode (не наследуется);
  используется в `InsertCharPre`;
- `pending` — снимок перед удаляющей клавишей: `{buf, row, chars, lines, t}` или `nil`.

Проверка «буфер подходит»: `vim.bo.buftype == ""`.
Проверка «Insert mode»: `nvim_get_mode().mode` начинается с `i` (включая `ic`, `ix`).

**`vim.on_key(key, typed)`** — вызывается до обработки клавиши, поэтому строка буфера
в этот момент отражает результат предыдущей клавиши:

1. `flush()` — применить `pending`, если он есть (см. ниже).
2. Если `typed ~= ""`: `user_insert = (Insert mode)`. Если `typed == ""` — значение
   наследуется (клавиша из раскрытия маппинга, повтора `.` или макроса относится к той
   пользовательской клавише, которая его вызвала; для `.` и `@q` это Normal mode,
   поэтому раскрытие игнорируется). `key_typed = (typed ~= "") and user_insert`.
3. Если не Insert mode, не `user_insert` или буфер не подходит — выход.
4. `key` ∈ {`<BS>`, `<C-H>`, `<C-W>`, `<C-U>`, `<Del>`} → `pending = снимок`.
5. `key` ∈ {`<CR>`, `<Tab>`} → `add(now, +1)`.

Сравнение `key` выполняется после маппингов (аргумент `key`, не `typed`), поэтому
стандартный маппинг `<C-W>` → `<C-G>u<C-W>` и маппинги автопар на `<BS>` обрабатываются
по фактически исполняемым клавишам.

**`InsertCharPre`**: если `key_typed`, буфер подходит и `v:char ~= "\t"` → `add(now, +1)`.
Символы из раскрытия маппинга (закрывающая скобка автопары) не учитываются, так как у
вызвавшей их клавиши `typed` пустой.
Табуляция исключена здесь, потому что `<Tab>` учитывается в `on_key` (иначе при
`noexpandtab` она была бы посчитана дважды, а при `expandtab` — ни разу).

**`flush()`** — вызывается в начале каждого `on_key`, на тике таймера и на `InsertLeave`:
- если текущий буфер ≠ `pending.buf` — сбросить `pending` без учёта;
- если число строк уменьшилось на `k` и курсор на строке `pending.row − k` (`<BS>` в начале
  строки) или `pending.row` (`<Del>` в конце строки) — `add(pending.t, −k)`
  (удалённые переводы строк);
- иначе если строка та же — `add(pending.t, −min(limit, max(0, pending.chars − strchars(текущая строка))))`,
  где `limit = 1` для `<BS>`, `<C-H>`, `<Del>` и не ограничен для `<C-W>`, `<C-U>`. Как в тренажёре,
  одно нажатие `<BS>` вычитает не больше одного символа: при `expandtab` и `softtabstop`/`smarttab`
  один `<BS>` в отступе удаляет до `shiftwidth` пробелов, набранных одним `<Tab>` или
  вставленных автоотступом;
- иначе — сбросить без учёта;
- `pending = nil`.

**Таймер перерисовки**: `vim.uv` таймер с интервалом 1000 мс, колбэк через
`vim.schedule_wrap`. Запускается в `add`, если таймер не запущен. На каждом тике:
`flush()`, `vim.cmd.redrawstatus({ bang = true })` (statusline всех окон); если `meter:empty(now)` — таймер останавливается.
Закрывается на `VimLeavePre`.

### init.lua

```lua
require('typingspeed').setup({
  unit   = 'wpm', -- 'wpm' | 'cpm'
  window = 10,    -- секунды, >= 3
})
require('typingspeed').status() --> "62 wpm" | "310 cpm" | ""
```

- `status()`: `cpm = meter:rate(now)`; `nil` → `""`; иначе значение в выбранных единицах
  (`wpm = cpm / 5`), округлённое до целого, плюс пробел и единица.
- `status()` до вызова `setup()` возвращает `""`.
- Повторный `setup()` заменяет конфигурацию и переустанавливает обработчики: augroup
  создаётся с `clear = true`, для `vim.on_key` используется один и тот же namespace.

Пример для lualine: `lualine_x = { require('typingspeed').status }`.

## Пример расчёта

За 10 с набрано 60 символов, 5 удалены `<BS>`: `net = 55`, `cpm = 330`, `wpm = 66`.
Если затем сделать паузу, значение плавно снижается; через 10 с без нажатий `status()`
вернёт `""`, и таймер остановится.

## Обработка ошибок

- `config.lua` проверяет опции через `vim.validate`: `unit` ∈ {`wpm`, `cpm`},
  `window` — число ≥ 3 (должно быть больше прогрева 2 с). При неверной опции `setup()`
  завершается ошибкой с именем опции и допустимыми значениями.
- Колбэки `on_key`, `InsertCharPre` и таймера выполняются в `pcall`. При первой ошибке
  трекер отключается (снимаются обработчики, останавливается таймер), и выводится одно
  сообщение через `vim.notify(..., vim.log.levels.ERROR)`. Это исключает повторяющиеся
  сообщения об ошибке на каждое нажатие клавиши.

## Известные погрешности

- Автопара через маппинг: при наборе `(` учитывается +1, а `<BS>`, удаляющий пару,
  даёт −2. Значение немного занижается.
- Удаление, затрагивающее несколько строк и не сводящееся к склейке строк, сбрасывается
  без учёта.
- Неисправленные ошибки учитываются как верно набранные символы.
- Удаление текста, вставленного без набора (автодополнение, сниппеты, аббревиатуры), вычитается,
  хотя этот текст не прибавлялся: например, `<C-W>` по принятому варианту автодополнения.
  Аббревиатура раскрывается через `<C-H>` и тоже даёт вычитание.
- Replace mode не учитывается.
- Первый символ, набранный в Select mode (плейсхолдер сниппета), не учитывается: клавиша
  приходит в режиме `s`.

## Тестирование

Внешних зависимостей нет. `tests/run.lua` загружает файлы `tests/*_spec.lua`, выполняет
функции-тесты в `pcall`, печатает результат по каждому тесту и завершает процесс с кодом 1,
если хотя бы один тест не пройден. Запуск: `make test`
(`nvim --headless --clean --cmd 'set rtp^=.' -l tests/run.lua`).

**meter_spec.lua** (время задаётся вручную):
- пустая очередь → `nil`;
- прогрев: события в течение 1,5 с → `nil`; через 2 с → значение;
- 60 символов за 10 с, −5 → 330 cpm;
- события старше окна удаляются; через `window` без событий → `nil`;
- `net` не уходит ниже 0 при преобладании удалений;
- после паузы длиннее окна `streak_start` начинается заново.

**tracker_spec.lua** (headless, `nvim_feedkeys(..., 'tx')`, подменённые часы, проверяется
`Σ delta` в `meter`):
- `iabc<Esc>` → +3; кириллица `iабв<Esc>` → +3;
- `iabc<BS><Esc>` → net 2; `iabc<C-H><Esc>` → net 2; `ifoo bar<C-W><Esc>` → net 4 и
  `iab cd<C-U>x<Esc>` → net 1 (со стандартными маппингами `<C-W>`, `<C-U>`);
- `<BS>` в отступе при `expandtab`, `softtabstop=4`: `i<Tab><BS>x<Esc>` → net 1;
- клавиши доходят до буфера без изменений; повторный `start()` не удваивает подсчёт;
  после `stop()` ничего не учитывается;
- `<CR>` и `<Tab>` при `expandtab` и `noexpandtab` → по +1 за клавишу;
- `<BS>` в начале строки и `<Del>` в конце строки (склейка) → −1;
- маппинг автопары `( → ()<Left>`: набор `(` → +1;
- вставка через `nvim_put` из маппинга → 0;
- повтор `.` и макрос `@q` → изменений нет;
- буфер с `buftype=nofile` → изменений нет;
- ошибка в колбэке отключает трекер и выводит одно сообщение;
- `status()` форматирует `wpm`/`cpm` и возвращает `""` без данных;
- `setup()` с `unit = 'foo'` или `window = 1` завершается ошибкой.
